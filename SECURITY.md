# Security Policy

## Reporting a Vulnerability

If you discover a vulnerability—such as data leaks via serial logs, dependency flaws, or local websocket buffer exploitation—please do not open a public GitHub issue. 

Instead, report vulnerabilities privately through the following disclosure process:

### How to Report
1. Email your findings.
2. In your report, please include:
   * A detailed description of the vulnerability.
   * Steps to reproduce the issue (or a proof-of-concept script).
   * The potential impact (e.g., system crash, data corruption).

### What to Expect
* **Acknowledgment:** You will receive an initial email acknowledgment of your report within **48 hours**.
* **Assessment:** The project maintainers will investigate the issue and send a status update within **7 business days** confirming whether the vulnerability has been accepted or declined.
* **Resolution:** If accepted, a security patch will be built and released in a minor version update. We will coordinate with you to provide proper attribution in our release notes if desired.
